# 识谱结果与任务控制

本模块把不可信模型文本转成独立音乐模型，并协调界面任务。不要在这里引入服务凭据、文件路径或 Electron 依赖。

## 结果处理

`score-result.ts` 生成原生 JSON 提示，解析纯 JSON 或单个 JSON 代码块，通过原生版本、严格结构及音乐语义校验。每页限双谱表钢琴、高音谱表在前、每谱表最多两个声部、最多 256 小节；完全没有事件的响应拒绝，真实休止符页面允许。

组合时按用户来源顺序追加小节，以谱表和声部位置映射声部，为所有实体重新分配有界且唯一的 ID，并重映射记号引用。原页面音乐不变，合并结果再次通过核心校验。来源图片、API Key 和服务配置不写入乐谱。

每页独立识别，不自动推断跨页调号上下文、修复跨页连线或合并分页小节。结构正确不代表音高、节奏识别正确；模型准确率另行评估。

## 界面控制

`controller.ts` 使用外部状态存储，串行协调配置、选文件、排序、执行和结果导入；运行期间允许独立取消。弹窗打开且任务繁忙时轮询状态，关闭弹窗不取消主进程任务。

接受结果通过 `DocumentController.importRecognition` 进入新文档流程，遵循保存、放弃或取消。忙碌或无效状态拒绝接受时保留识谱结果；取消文档替换保留当前编辑。识谱本身可以与当前音乐编辑并行，只有用户明确接受才切换文档。

首次导入真正成功后，DocumentController 将主进程提供的来源页/小节关联绑定到当前文档能力。失败、取消或切换文档不能误绑定。重试成功后可显式按来源顺序补入当前谱，或选择追加到末尾；只加入缺失页，保留现有小节、标题、实体 ID、保存路径与用户修改。

merge.ts 校验来源关联、映射新增声部并为新增实体生成全新 ID，通过通用 insert-measures 命令形成一个批量事务。现有跨页延音线、来源重排或定位点冲突阻止按序插入；用户可选择追加末尾或创建新谱。获取结果期间若文档能力或音乐快照变化，则拒绝此次补入。成功页重复点击不能重复插入；撤销后的页可重新补入，重做后不会重复。

来源关联只保存在当前会话：保存/另存为保留，重新打开、恢复或重启不重建。不修改原生 JSON 版本，不在乐谱中存储图片、Key 或服务配置。任务持久化和跨页纠错仍留给后续独立设计。

## 验证

`pnpm test` 验证排序、繁忙操作隔离、运行中取消、拒绝导入后的结果保留；主进程测试覆盖结果校验与引用重映射，文档控制器测试覆盖替换失败、取消与普通编辑保存。新增合并回归覆盖中间缺页、手动音高/标题保留、新声部与记号重映射、防重复、撤销/重做、跨页延音线拒绝、明确追加、异步竞争及文档切换。桌面测试见 `tests/e2e/recognition.spec.ts`，使用本地假服务模拟部分失败、先导入并编辑、再重试补入、保存与历史，不调用真实模型。
