# 独立音乐核心与编辑命令

Status: resolved
Type: task
Blocked by: 01

## 目标

在 `src/core/` 建立与 React、Electron、Verovio 和 AI 输出格式无关的音乐核心。先实现可以支持钢琴编辑、撤销与保存的基础结构，再逐步扩展已确认的首版记号。

## 范围

- 乐谱、小节、谱表、声部、音符/休止事件及和弦音符的稳定标识。
- 区分记谱音高与实际音高，明确音名、变音、八度，不将绘制坐标作为音乐内容。
- 用精确有理数表示音乐时间，支持附点与三连音；不将基准的固定 12 ticks 当作产品通用时值模型。
- 显式引用记号的起止对象，区分延音线和连奏线。
- 基础插入、删除、修改命令，错误时不部分修改；撤销/重做恢复稳定身份与音乐内容。
- 带版本号的原生 JSON 编解码与领域校验；未来版本和损坏引用需明确报错。
- 保持用户数据与当前排版布局分离，为五线谱、简谱及播放提供同一份内容。

## 验收

- 覆盖双谱表、多声部、和弦、精确时值和跨小节延音的领域测试。
- 命令前后与撤销/重做结果可验证；拒绝无效输入时保留原内容。
- 保存/重开保持音乐语义与稳定标识，未知版本或损坏文件不得静默解释。
- 核心不依赖浏览器 DOM 或 Electron；遵循 AGENTS.md 的注释与可维护性规则。
- 运行 pnpm 类型、静态检查和针对核心行为的测试。

## Comments

- Q33 已确认实施顺序；本任务从领域核心开始，不以评估脚本的数据结构替代正式模型。
- 排版候选暂为 Verovio，领域接口不得依赖其 MEI 或实验性编辑 API。

## Answer

已实现 [音乐核心](../../../src/core/README.md)，公共入口为 `src/core/index.ts`。
包含独立音乐模型、和弦逐音标识、精确分数、记谱与实际音高、领域校验、原子编辑命令、快照撤销/重做、保存状态及版本 1 原生 JSON 编解码。
延音线按音符引用校验跨小节连续性，批量修改在最终状态统一校验；明确删除音乐事件会清理相关记号，替换导致的损坏引用需在同一事务中修复。
增加手写双谱表、三声部原生谱例和 39 个 Node 核心测试，覆盖事务失败保护、异步保存状态、损坏引用、未知字段与未来版本拒绝。
第一版没有历史文件格式需要迁移；后续格式变化采用显式版本策略。显式连音组、弱起小节和复杂跨谱表记号列为后续工作。
类型检查、ESLint、Prettier 和生产构建通过；尚未接入谱面界面和桌面磁盘读写。
