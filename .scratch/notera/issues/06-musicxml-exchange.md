# MusicXML 乐谱交换

Status: resolved
Type: task
Blocked by: 05

## 目标

将现有钢琴乐谱与其他记谱软件交换，使导入内容进入同一音乐核心，保留普通编辑、原生保存、排版和撤销能力。

## 范围

- 明确首版 MusicXML 支持矩阵，以官方规范和当前核心模型为依据，记录无法表示的内容。
- 支持常见未压缩 MusicXML 与压缩 MXL 的安全读写；先核查解析/压缩依赖的许可与维护成本，不引入自编 C++。
- 建立独立的导入/导出适配，保持原生模型与命令独立于候选排版引擎。转换结果经过核心校验。
- 钢琴双谱表、多声部、和弦、休止、变音、拍号/调号变化、附点/连音、延音线/连奏线、力度、踏板与基础重复按支持矩阵处理。
- 稳定保留可表达的音乐时间与身份，明确报告导入/导出损失，不能静默将不支持的音乐替换为看似成功的结果。
- 通过主进程授权的文件选择接入界面，延续当前保存/放弃/取消流程；解析失败不替换当前有效文档。

## 验收

- 使用原创、人工确认的钢琴谱例，检查原生 → MusicXML → 原生的语义往返，并验证另一记谱软件可读。
- 外部钢琴谱导入后可编辑、撤销、保存与重开。
- 覆盖多声部时间推进、跨小节连线、损坏 XML/MXL、不支持内容和操作取消。
- XML 与归档解析需要限制资源用量和外部引用；建立可复现测试、交换说明及明确的兼容范围。

## Comments

- 按已确认的实现顺序，在原生文件工作流后、试听与 PDF 导出前完成。
- MusicXML 是交换格式，不能成为原生文件或编辑模型的权威数据源。

## Answer

- 新增独立 `src/exchange/`：受限 XML/MXL 读取、精确时间解释、和弦/声部、常用连线/方向/反复、MusicXML 4.0 导出与可选实体身份元数据，导入最终通过音乐核心校验。
- 钢琴支持矩阵、损失确认、明确拒绝范围、归档/引用资源限制与依赖许可/维护成本见 `src/exchange/README.md`。
- 主进程授权原生文件对话框，导入提示无法保留的内容后才替换文档与恢复；导入为未保存的普通原生乐谱。导出不改变原生路径、未保存状态或恢复内容。
- 添加独立手写外部谱例、往返/跨度/损坏/伪造归档测试和真实桌面闭环。80 个单元测试通过；5 个生产桌面测试及 5 个 macOS arm64 未签名打包应用测试通过。
- 官方 v4.0 XSD 验证原创导出与外部谱例通过，新增 `pnpm run verify:musicxml` 复现命令。Verovio 独立 MusicXML 读取器在移除 Notera 元数据后读谱、检查音符/连线并输出 SVG；尚未人工检查 MuseScore/Dorico GUI 互操作，版式不是无损交换承诺。
- lint、typecheck、build、format:check 与 git diff --check 通过；截图为忽略的 `logs/musicxml-exchange-preview.png`。
- 下一步见任务 07 钢琴试听与谱面跟随，然后任务 08 五线谱 PDF 导出。
