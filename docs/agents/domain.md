# Domain Docs

## Before exploring

Read root `CONTEXT.md` for domain vocabulary and relevant ADRs
under `docs/adr/` for architectural decisions.

If these documents do not exist, proceed silently.
The domain-modeling skill creates them when terms or decisions
are resolved.

## Layout

Use a single context:

- `CONTEXT.md`: domain glossary and model.
- `docs/adr/<NNNN>-<decision-slug>.md`: architectural decisions.

## Vocabulary and decisions

Use glossary terms consistently in issues, code, tests,
and proposals. Record genuine terminology gaps for domain-modeling.

Explicitly identify proposals that conflict with an existing ADR
and explain why the decision should be reconsidered.
